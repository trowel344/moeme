# L4-24GB track: 31 h/month — the 9B program

9B bf16 is ~18-19GB: fits L4 for frozen work and (with 8-bit base) for
late-layer training. 9B is the scale between proxy (0.8-2B, laptop) and
target (27B, A100): whatever fails here at 9B will fail worse at 27B.

Setup (same as Lightning README: bitsandbytes, causal-conv1d, HF login).

## Job 1 — 9B frozen MoCM oracle, all layers (~1 h)

The no-training ceiling at 9B scale, E8/k1 and E32/k1:

```bash
python3 experiments/upcycle_poc.py --model Qwen/Qwen3.5-9B \
  --experts 8 32 --topks 1 --layers all --frozen-only \
  --eval-blocks 4 --corpus-chars 4000000 \
  --out results/upcycle_9B_frozen.json
```

Decides: does the 0.8B oracle curve (0.86 at E8 → 0.93 at E64) hold at 9B,
or does structure emerge with scale? If E8 oracle is still >0.8, slicing is
dead at every scale tested.

## Job 2 — 9B depth map + distill easy-4 (~2 h)

```bash
python3 experiments/mocm_depth.py --model Qwen/Qwen3.5-9B \
  --out results/depth_9B.json
# then distill the bottom-4 from that map at 25%, 1500 steps:
python3 experiments/mocm_distill.py --model Qwen/Qwen3.5-9B \
  --layers <BOTTOM4> --frac 0.25 --steps 1500 \
  --save $OUT/distill_9B.pt --out results/distill_9B.json
```

Decides: does partial distillation transfer (1.15x @0.8B, 1.36x @2B)?
The trend across 0.8/2/9B predicts the 27B outcome better than any theory.

## Job 3 — 9B MoCM trained late-4 (remainder, ~4-6 h)

```bash
python3 experiments/mocm_poc.py --model Qwen/Qwen3.5-9B --load-bit 8bit \
  --cell mocm25 --steps 300 --out results/mocm_9B.json
```

Note: `mocm_poc.py` has no `--load-bit` yet — it loads full bf16 (18GB,
fits L4 frozen; training late-4 adds ~5GB Adam, still fits). If OOM, this
job ports the `--load-bit` pattern from `upcycle_poc.py` first (30 min).
