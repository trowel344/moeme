# A100-40GB track: 10 h/month — real activations + dry runs

The 40GB card cannot train 27B comfortably, but it can *measure* it: 8-bit
backbone (~28GB) plus full-model forwards for activation capture. Its highest
value is replacing every synthetic-input number in this repo with real ones.

## Job 1 — 27B real-activation oracle table, all 64 layers (~2-3 h)

```bash
python3 experiments/upcycle_poc.py --model Qwen/Qwen3.8-27B --load-bit 8bit \
  --experts 8 --topks 1 --layers all --frozen-only \
  --seq-len 256 --eval-blocks 2 --corpus-chars 2000000 \
  --out results/upcycle_27b_oracle.json
```

This captures dense MLP in/out on real tokens for all 64 layers, then scores
the frozen E8/k1 oracle per layer. Output kills or confirms three open items
at once: the synthetic-input caveat on `results/mocm_bytes.json`, the
late-layer hypothesis at 27B (is layer 23 special here?), and the exact
per-layer width map an adaptive conversion would need.

VRAM: 8-bit base 28GB + one layer's expert materialization at a time.
If tight: `--eval-blocks 1`, `--seq-len 128`.

## Job 2 — gate dry-runs (remainder)

Short training probes that validate the 80GB month-one command without
spending 80GB hours: E8/k1 on 2 late layers, 50 steps, checking step time,
memory headroom, and checkpoint/resume. Scale the step cost × layers ×
experts to price the 80GB jobs exactly.

```bash
python3 experiments/upcycle_poc.py --model Qwen/Qwen3.8-27B --load-bit 8bit \
  --experts 8 --topks 1 --layers 62 63 --steps 50 --max-seconds 5400 \
  --out results/upcycle_27b_probe.json
```

Never debug on 80GB hours. Debug here.
